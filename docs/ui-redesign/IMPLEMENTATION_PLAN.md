## 2. Ownership and repo rules that shape the plan

- `apps/mobile`, `packages/tokens`, `packages/i18n` (mobile copy): owner Trang. Phases 1–5 stay inside these.
- `apps/web`, `packages/ui-web`: unchanged and out of scope for this pass.
- `packages/tokens` is shared. Adding v2 tokens is additive; removing the old palette is a separate PR once nothing imports it (more than 20 lines deleted → ask first, per RULES §3).
- Strings go to `@tripflix/i18n`, API calls go through `@tripflix/api-client`, colours come from tokens. No new libraries without asking (the plan needs none: Ionicons, Reanimated 4, expo-image and expo-video are already installed).
- **Deploy risk:** `develop` auto-deploys the web to tripflix.io.vn. Web redesign PRs must be complete per route when merged, or kept behind a route-level switch. Mobile has no auto-deploy.
- Each phase: lint, typecheck and test pass; evidence file `docs/evidence/SCRUM-189-<phase>.md` with Android screenshots next to the Stitch PNG; PR into `develop` with a merge commit. No AI co-author lines (RULES §6).

## 3. Phases

### Phase 1 — Route and contract verification (no UI change)

- For each of the 38 mobile routes: live API or fixture, auth requirement, current states, and the I/A/U/F class of each Stitch element. Output: an appendix table in `STITCH_DESIGN_MAPPING.md`.
- Confirm which fields exist for: feed counts, verified-trip flag, topics, reviews, profile preferences, saved collections, notification count.
- Mark `apps/mobile/README.md` "sample data" as stale (a docs fix in its own commit).
- **Exit:** every Stitch element on the 10 screens has a confirmed class.

### Phase 2 — Foundations

- `packages/tokens`: add `v2` (semantic Day/Night colours, type roles, spacing, radius, elevation, motion) beside the old palette. Extend `tokens.css` and the existing parity test so CSS and TS stay in sync. Add a contrast unit test that asserts every text/background pair in §2.3 of the design system.
- `apps/mobile/src/components/ui/` (new, v2 only): `Text`, `Button`, `IconButton`, `Chip`, `Field`, `Sheet`, `MediaCard`, `PriceBlock`, `TrustBadge`, `PreviewBadge`, `StateScreen` (empty/loading/error/offline/signed-out), `Skeleton`, `Timeline`. Each with a11y roles, pressed/disabled/loading states and Reduce Motion handling.
- A gallery route (dev-only) that renders every component in Day and Night for screenshot review.
- **Exit:** gallery screenshots on Android pass the §12 checklist items that apply to components.

### Phase 3 — Mobile shell and navigation

- Preserve the existing Reels screen and original bottom menu per D2. Update only mobile screen surfaces and shared components around them.
- Keep the existing behaviours: onboarding redirect once, `compose` → `/create` or login with `returnTo`, hidden `inbox`.
- **Exit:** existing tab and deep-link behaviour remains reachable; the unread badge placement and screen-reader tab order remain correct.

### Phase 4 — Watch and discover (Stitch 3.1, 3.2, 3.3, 3.8)

Explore home, search composer and results, hotel results and detail, flight results and creator profile adopt the Day system. Reels stays unchanged per D2. Map, deals, car/tour and personalisation remain preview/future items where unavailable.

- **Exit:** search, filters, like/save/share/comment, follow and auth return all work against the live API; empty and error states are designed.

### Phase 5 — Plan, book, account, create (Stitch 3.4, 3.5, 3.6, 3.7, 3.9, 3.10)

Itinerary detail and timeline, customise and trip builder, cart, checkout, VNPay return, success, booking detail and cancel; onboarding; Tripi assistant; saved; account hub, my trips, notifications, moderation status, settings; creator studio retains the existing `uploadVideo` flow. The AI caption suggestion remains a disabled preview.

- **Exit:** a full booking run on staging data (search → itinerary → cart → VNPay sandbox → success → booking detail → cancel); totals match `app-core`; state survives the login redirect.

### Deferred — Web

No web or admin implementation is included in this work. Any later web redesign requires a separate scope and approval from its owner.

### Final mobile review

Review the implemented mobile routes and states against Stitch, confirm the preserved Reels/menu, and document screens that could not be reviewed because of authentication, API or device availability. Do not remove the legacy palette as part of this pass.

## 4. Risks

| Risk                                                        | Impact                                       | Handling                                                                                                                                     |
| ----------------------------------------------------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Stitch not exportable or out of date                        | Fidelity drifts                              | D5. Each review compares against the PNG; deliberate deviations are recorded in evidence.                                                    |
| The API lacks fields Stitch shows (counts, topics, reviews) | Empty-looking screens                        | Omit the field or use the Preview pattern. Never fake it. List gaps for BE owners (Phong feed, Thành social, Duy discovery, Thắng commerce). |
| No real video playback yet                                  | Reels feel static                            | Cover image + clear "video đang được xử lý" if the API sends no media URL. Track the dependency in mapping §6.                               |
| Tab rename breaks deep links or analytics                   | Lost events                                  | Keep route file names (`book`) and change only label and content. Check analytics event names before renaming.                               |
| Two token sets co-exist for a while                         | Inconsistent screens                         | Migrate whole screens, never half a screen. Phase 7 removes the old set.                                                                     |
| Web auto-deploys from `develop`                             | Out-of-scope changes could affect production | No web files are included in this pass.                                                                                                      |
| Contrast on video frames varies                             | Unreadable captions                          | Scrim tokens tested on bright frames (beach, snow, sky) in evidence.                                                                         |
| Dynamic type at 200 %                                       | Clipped Vietnamese labels                    | Part of every evidence set.                                                                                                                  |

## 5. Verification per screen

1. Side-by-side: Stitch PNG vs Android screenshot (Day/Night as applicable).
2. §12 checklist of `NEW_DESIGN_SYSTEM.md`, recorded as a table in the evidence file.
3. Functional run of the route's flows against the live API, including auth return.
4. State captures: loading, empty, error, offline (airplane mode), signed-out.
5. Widths 320 and 430, 200 % text, Reduce Motion on, TalkBack pass on the main task.
6. `pnpm turbo run lint typecheck test --affected` results pasted as real output.
7. Confirm no backend contract changed (`git diff` touches no `contracts/` or generated client).

### Issues found while reviewing

- **Fixed:** a hook (`useWindowDimensions`) was called after an early `return` in `live-feed-screen.tsx`, which breaks the rules of hooks when the session becomes ready. It now runs before the return.
- **Fixed:** hard-coded colours and Vietnamese strings in the new Đã lưu and Tạo bài code moved to tokens and `@tripflix/i18n`; the uppercase "TRIPFLIX STUDIO" label was removed.
- **For the backend owners (not changed here):** hotel images from `d399hxccn6y84z.cloudfront.net/dev/trang/images/hotels/...` return HTTP 403 in the local environment, so no hotel photo loads. The app now shows the fallback; the photos themselves need the CDN or bucket access fixed.

About 85 mobile files still style locally with the legacy `colors` palette. They sit on the v2 primitives but need a per-screen pass; the legacy palette stays until a later cleanup. The Android emulator review and the remaining booking screens above are the next round.
